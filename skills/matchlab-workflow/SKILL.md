# Matchlab workflow

1. **Freeze the question and deck.** Recover the newest relevant export or authenticated played list. Save exact bytes and SHA-256 under the existing project's private evidence directory; preserve zones, counts and printings. Label proposed / confirmed / played / last-known-good separately. Record format and platform; leave unstated facts unknown. Do not substitute an older proposal or silently cut/pad cards.

2. **Discover before inventing a test.** Work in `~/projects/mtg-matchlab`. Run `python3 matchlab.py tools --json`; read `docs/TOOLS.md` and only the selected tool's guide. Use `draw` for exact draw math, `mana` for isolated-target feasibility, and documented opening tools only within their supported models. If an advertised experimental opening fixture/guide is absent, inspect the actual implementation and existing tests rather than guessing its schema. A body-only keep policy can heavily over-mulligan ramp/removal decks; run policy sensitivity, retain unsupported spells as inert real slots, and do not treat that test as full-engine opening validation. Forge `audit` establishes input/script support; `run` is preboard AI gameplay, never human win rate. Read README/SETUP before Forge use. Verify the runner accepts the exact proposed player: all card scripts existing does not make a pinned historical-player CLI a custom-player runner. Do not overwrite that baseline or substitute its games for the proposal.

   **Bounded frozen-deck validation:** use existing opening/mana engines, preserve every physical card slot and quantity, and keep the user's sample/time budget explicit. Read [bounded opening, mana, and basic-replacement validation](references/bounded-opening-mana-resilience.md) for strict/relaxed London-policy sensitivity, land-model transcription, and inventory-conserving two-loss payment checks. Body-only tools must leave ramp, selection, planeswalkers and removal as nonbodies with unsupported effects labeled—not substitute fake creatures. Report policy sensitivity separately from deck quality. Replacement checks must start from originally sufficient mana, conserve actual basics after unavailable reserves and each fetch, and declare their finite state domain; fixture success is never an exhaustive gameplay claim. Retain scripts/configs/raw outputs and verify finalized artifact hashes, excluding self-referential manifest entries and still-changing logs.

3. **Verify identities and choose relevant checks.** For printing-aware counts/curve or supported artifact-resource questions, read `docs/ARTIFACT_AUDIT.md`. Obtain exact SET/collector Scryfall records with source URLs and retrieval times; verify input names against full/front identities, preserve preparation faces, and refresh evidence when a current-data claim requires it. Follow that guide's Oracle-bundle schema. Preserve each record's actual network `retrieved_at` when assembling or copying bundles; use a separate `assembled_at` for packaging. A new deck revision does not refresh cached Oracle evidence. If the original retrieval time is unavailable, disclose that or re-fetch rather than stamping cached data with the current time. Exact-printing identity validation must accept the full Oracle name or the verified front-face name, while still retaining every face's text. Never substitute fuzzy matches, invent text, or equate a missing Arena printing ID with unavailability.

   Set `deck_file`, `oracle_bundle`, and a new `report_file` to this exact version's files, then run:
   ```sh
   cd ~/projects/mtg-matchlab
   python3 matchlab.py artifact-audit "$deck_file" --oracle "$oracle_bundle" > "$report_file"
   ```
   Cross-check derived metric labels against the exact type lines before relying on them. Artifact lands are artifacts but are not artifact spells: if an `artifact_spell_cards` report includes a land, preserve the raw report, flag the discrepancy, and separately reconcile nonland artifact counts instead of propagating the mislabeled number or treating dependent availability math as validated. Printing-level Arena warnings require card-level resolution (especially old basic-land printings), not automatic card rejection. The report's `format_confirmed_by_user` flag may remain false even with `--format`; preserve conversation-confirmed format separately in the evidence manifest.

   Add `--format standard` only for a confirmed format or explicitly labeled assessment. Add `--scenarios "$scenario_file"` only when its declared checkpoints address this deck and the checker supports the effects. The Gruul examples are regression examples, not mandatory checks for every deck. Read the result and exit status; expected scenario rejection can be useful evidence.

   **Brawl commander-zone boundary (both sizes):** The artifact-audit parser supports `Deck`/`Sideboard`, not `Commander`. Preserve the actual Arena export separately and audit commander and library in separate Deck-only views, documenting the mapping. For 100-card Arena Brawl use a 99-card library and the `brawl` legality field; do not substitute Commander or Standard Brawl legality. Names-only user imports can avoid binding to unavailable artwork printings, while retaining exact-printing audit views and an explicit identity mapping. For 60-card Standard Brawl, follow the additional checks below. Validate the actual `standardbrawl` legality field, singleton limits, commander eligibility and color identity explicitly; a Standard assessment is not equivalent. Draw/opening populations exclude the commander (59 cards for the 60-card format). Do not force an exact-60 opening model to fit by adding the commander to the library. Label bounded manual opening/payment checks and omitted Brawl mulligan rules honestly. Resolve missing selected-printing Arena IDs through released alternate printings when useful for an import; missing IDs alone do not reject a card.

4. **Close the work.** Report the exact version/hash, tested question, command and saved evidence, material findings, and unsupported assumptions. Keep detailed traces private. Separate count/rules checks, bounded scenarios, opening tests, and actual games. Unsupported effects block that claim, not unrelated useful work: complete supported checks and an authorized repair, rerun affected checks, and label the remaining gap. Never convert a resolved scenario into a matchup prediction or alter the user's deck without authorization.

5. **Make handoffs usable.** When handing work off, include scope/question, deck path+SHA-256+version status, format/platform, Oracle bundle+retrieval date, command, report/config/scenario paths, seed/sample limits if applicable, unsupported mechanics, and next action. The recipient reads the artifacts, checks the deck hash, and acknowledges the version before continuing. Mark receipt unverified until acknowledged; a message or saved note alone does not prove the other bot loaded it.
